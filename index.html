01 — OPERATOR

      
The operator

    

    

      

        
I design systems that don't just execute — they plan, verify, and correct their own mistakes. Most of what follows is built without the usual shortcuts: a RAG pipeline with no LangChain, an ETL sync layer with no framework, agents that grade their own code before it ships. I like knowing exactly what's happening inside the machine, so I built the machine myself first.

        
The rest of the stack is glue for the real world — n8n pipelines that turn WhatsApp messages into freight manifests, Gmail threads into drafted replies, and stock watchlists into AI-scored reports. Different problem, same instinct: reduce a repetitive judgment call to a system that can be trusted to run on its own.

        ENTRY 01
        PYTHON · LANGGRAPH
      

      
Agentic-Coder

      
A coding assistant that plans, writes, tests, and rewrites its own output.

      

      
↺ On FAIL, the Tester routes control straight back to the Coder for another pass.

      
Four LangGraph agents stand in for one overworked LLM call. A Planner scopes the task, a Coder writes it, a Tester reviews the diff and returns PASS or FAIL — no human in the middle until the summary lands.

      

        PythonLangGraphLangChainOpenRouterpython-dotenv
      

      
    
        
  • Custom AgentState extends MessagesState, tracks review_status
    • 
        
  • Tool-calling read_file() lets agents inspect their own output
    • 
        
  • Conditional-edge router loops failures back to the Coder
    • 
        
  • Ships coder.py + testing.txt as final deliverables

        PYTHON · LANGGRAPH
      

      
OpenEdu-Orchestrator

      
A multi-agent sync layer that moves a university's data into an ERP with no API to talk to.

      

      
The Orchestrator owns sync state and watches every other agent's clock.

      
Four agents, one job each. It bulk-migrates PIEAS records into an OpenEduCat/Odoo-style target, then keeps them in sync with watermark-based change detection and a full ID diff for deletions — none of it touching a dirty flag.

      

        PythonLangGraphSQLitepytestClick
      

      
    
        
  • Three isolated cycles: bulk migration, watermark sync, deletion diff
    • 
        
  • Archival deletes only — every removal stays reversible
    • 
        
  • 57 pytest cases across three mock databases
    •

        ENTRY 04
        PYTHON · NO FRAMEWORK
      

      
RAG-from-Scratch

      
Retrieval-augmented generation with zero LangChain, zero LlamaIndex.

      

      
Cosine similarity is computed by hand — dot product over magnitude, no shortcuts.

      
Every stage a framework usually hides is hand-built here: chunking with manual overlap, Sentence-Transformer embeddings, hand-coded cosine search with raw NumPy, and a prompt assembled from whatever the retriever returns. Built to understand the machine, not just call it.

      

        PythonPyPDFSentence-TransformersChromaDBNumPy
      

      
    
        
  • 1000-char chunks with 100-char overlap to preserve boundaries
    • 
        
  • Follow-ups rewritten into standalone queries before retrieval
    • 
        
  • Conversation memory kept separate from retrieved-chunk context
    • 
        
  • Single-responsibility files: embedding.py, cosine_similarity.py...
    •
